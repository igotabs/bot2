# Telegram-бот: розгортання на VPS

Інструкція для провайдера: запуск бота через Docker Compose, збереження Excel-звітів на SMB-шарі та постійне зберігання робочого стану.

## Що зроблено

### `docker-compose.yml`

Інфраструктура описана в одному файлі:

- Сервіс `bot` збирається з наявного `Dockerfile`.
- `restart: unless-stopped` забезпечує автоматичний перезапуск після завершення процесу та запуск після перезавантаження VPS, якщо контейнер не був зупинений вручну й служба Docker запускається автоматично.
- `init: true` забезпечує передавання сигналів процесам і прибирання завершених дочірніх процесів. У боті передбачена обробка `SIGTERM` для коректного завершення.
- SMB-шара `\\10.10.110.146\share` підключається як CIFS-том у `/mnt/share`.
- Звіт записується за шляхом `EXCEL_PATH=/mnt/share/reports/reports.xlsx`. Папка `reports` створюється під час запуску командою `mkdir -p`.
- Локальний іменований том `bot_data` монтується в `/data` і зберігає чергу повторних спроб, дані дедуплікації, deep-link-мапу та lock-файл між перевстановленнями контейнера.
- Lock-файл розташований на локальному томі, щоб блокування не залежало від особливостей CIFS.
- Налаштовані healthcheck за lock-файлом і ротація логів.

Статус `unhealthy` сам по собі не запускає перезапуск за політикою `unless-stopped`: вона реагує на завершення контейнера. Перевірка lock-файлу також не замінює перевірку доступності Telegram і SMB. [Документація Docker про перезапуск](https://docs.docker.com/engine/containers/start-containers-automatically/).

### `.secrets`

Файл містить конфіденційні налаштування й інструкцію із заповнення. SMB-блок попередньо заповнений; `BOT_TOKEN` і `NOTIFY_CHAT_ID` провайдер указує самостійно.

### Виключення з Git і Docker-образу

До `.gitignore` та `.dockerignore` додані `.secrets`, `deeplinks.json`, `notified_ids.json`, lock- і pid-файли.

Робочі паролі потрібно зберігати в `.secrets`. Якщо вони також записані як значення за замовчуванням у `docker-compose.yml`, ігнорування `.secrets` не приховує ці копії: перед комітом приберіть робочі секрети з Compose-файлу. Файли, які вже відстежує Git, потрібно окремо прибрати з індексу; додавання до `.gitignore` не видаляє їх з історії.

### `utils/deeplink.py`

Шлях до сховища deep-link-мапи читається зі змінної `DEEPLINK_PATH`. У контейнері вона має вказувати на файл у `/data`, щоб мапа зберігалася на постійному томі.

## Де зберігаються дані

| Дані | У контейнері | На сервері або в Windows |
| --- | --- | --- |
| SMB-шара | `/mnt/share` | `\\10.10.110.146\share` |
| Excel-звіт | `/mnt/share/reports/reports.xlsx` | `\\10.10.110.146\share\reports\reports.xlsx` |
| Медіафайли | `/mnt/share/reports/media` | `\\10.10.110.146\share\reports\media` |
| Черга, дедуп, deep-link-мапа, lock-файл | `/data` | Локальний Docker-том `bot_data` |
| Власні тексти інтерфейсу | `/app/secret.xlsx` | Файл `secret.xlsx` у корені проєкту, доданий до образу |

Іменований том зберігається після перевідтворення контейнера на тому самому VPS. Це не резервна копія: для перенесення на інший сервер потрібне окреме перенесення даних. Під час оновлення зберігайте назву Compose-проєкту, щоб використовувався той самий том. [Документація Docker про томи](https://docs.docker.com/engine/storage/volumes/).

## Вимоги до VPS

- Ubuntu з Docker Engine і Docker Compose v2.
- Доступ до Telegram API.
- Мережевий маршрут до `10.10.110.146` та доступ до SMB через TCP-порт `445`. Це приватна адреса: VPS має бути в потрібній мережі або підключатися до неї через VPN.
- Підтримка CIFS у ядрі Linux; пакет `cifs-utils` для роботи з CIFS на хості.
- SMB-обліковий запис із правами створення папок і запису файлів у `share\reports`.

## Одноразова підготовка Ubuntu

Для нового VPS на **Ubuntu 24.04** можна використати пакети з репозиторіїв Ubuntu; `docker-compose-v2` доступний у компоненті `universe`. [Пакет Docker Compose v2 для Ubuntu 24.04](https://packages.ubuntu.com/noble/docker-compose-v2).

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2 cifs-utils
sudo systemctl enable --now docker
sudo docker compose version
```

Якщо потрібного пакета немає у вашому випуску Ubuntu, встановіть Docker Engine і `docker-compose-plugin` за [офіційною інструкцією Docker](https://docs.docker.com/engine/install/ubuntu/). Вона містить налаштування репозиторію Docker; пакети цього способу встановлення не слід змішувати з `docker.io`.

Наведені далі команди виконуйте з кореня репозиторію, де лежить `docker-compose.yml`. Для доступу до Docker використано `sudo`; провайдер може його прибрати, якщо обліковий запис деплою вже має відповідні права.

## Налаштування `.secrets`

Отримайте підготовлений `.secrets` окремо від Git-репозиторію та розмістіть його поруч із `docker-compose.yml`. Збережіть наявний SMB-блок і заповніть налаштування бота.

| Змінна або блок | Що вказати |
| --- | --- |
| `BOT_TOKEN` | Токен від `@BotFather`; можна перенести з чинного локального `.env` |
| `NOTIFY_CHAT_ID` | ID чату для сповіщень; отримати командою `/myid` у вже запущеного бота |
| SMB-блок | Попередньо заповнені реквізити облікового запису `smbuse`; імена змінних мають відповідати `docker-compose.yml` |
| `SMB_VERS` | Версія SMB, яку підтримує сервер; змінювати за потреби |
| `SHAREPOINT_*` | Заповнити відповідно до конфігурації проєкту, якщо використовується SharePoint |

Фрагмент формату:

```dotenv
BOT_TOKEN=PASTE_BOT_TOKEN_HERE
NOTIFY_CHAT_ID=PASTE_CHAT_ID_HERE

# Нижче збережіть наявний SMB-блок.
# За потреби додайте налаштування SHAREPOINT_*.
```

Значення `PASTE_...` потрібно замінити. Один запис `KEY=VALUE` розміщуйте на окремому рядку, без пробілів навколо `=`. Рядки з `#` є коментарями. Для звичайних значень лапки не потрібні; значення з буквальним `$` можна взяти в одинарні лапки, щоб Compose не виконав підстановку. [Правила dotenv у Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/#env-file-syntax).

Обмежте доступ до файлу:

```bash
chmod 600 .secrets
```

Файл має бути доступний обліковому запису, який запускає Compose. Зберігайте робочу копію на VPS і не комітьте її.

### Як Compose використовує файл

Два механізми виконують різні завдання:

- `--env-file .secrets` передає значення для підстановок `${...}` у `docker-compose.yml`, зокрема для параметрів CIFS-тома.
- `env_file: .secrets` у налаштуваннях сервісу `bot` передає змінні в середовище контейнера, де бот читає їх через `os.getenv`.

Самого прапорця `--env-file` недостатньо для автоматичного передавання всіх змінних у контейнер: для цього потрібен `env_file:` або `environment:`. [Налаштування `env_file` у Compose](https://docs.docker.com/reference/compose-file/services/#env_file).

## Деплой і CD

Перед першим запуском перевірте, що `.secrets` заповнений і SMB-сервер доступний із VPS.

Перевірка синтаксису конфігурації без виведення її вмісту та запуск:

```bash
sudo docker compose --env-file .secrets config --quiet
sudo docker compose --env-file .secrets up -d --build
```

Перевірка стану та перегляд логів:

```bash
sudo docker compose --env-file .secrets ps
sudo docker compose --env-file .secrets logs --tail=100 bot
```

Команду `up -d --build` також викликає CD-пайплайн після успішного оновлення репозиторію. Наприклад:

```bash
git pull --ff-only && sudo docker compose --env-file .secrets up -d --build
```

Обліковий запис CD має мати доступ до Docker, репозиторію та `.secrets`. Робочий каталог і назва Compose-проєкту повинні залишатися сталими.

Для звичайного оновлення не потрібен `down`. Не використовуйте `docker compose down -v` або очищення томів під час редеплою: це може видалити локальний стан у `bot_data`.

## Діагностика SMB

Якщо з'являється `mount error(112)` або `Host is down`, перевірте:

1. Чи працює маршрут або VPN до `10.10.110.146` і чи доступний TCP-порт `445`.
2. Чи запущений SMB-сервер і чи існує шара `share`.
3. Чи правильні реквізити в `.secrets` і чи дозволено запис у `reports`.
4. Чи відповідає `SMB_VERS` можливостям сервера — наприклад, `3.0` або `2.1`.

Помилка `Host is down` сама по собі не доводить несумісність версії SMB. Не переходьте на застарілий SMB `1.0` як стандартний спосіб її виправлення.

Після зміни параметрів CIFS може знадобитися перестворити саме визначення мережевого Docker-тома: наявний том може зберігати старі параметри драйвера. Локальний том `bot_data` зі станом бота потрібно зберегти.

## Власні тексти інтерфейсу

Без файла власних текстів `secret.xlsx` або `secret.csv` бот використовує вбудовані тексти.

Для власних текстів покладіть `secret.xlsx` у корінь проєкту перед збиранням образу. Налаштований шлях:

```dotenv
CONFIG_FILE=/app/secret.xlsx
```

Переконайтеся, що файл включений у копіювання в `Dockerfile` і не виключений через `.dockerignore`, після чого виконайте повторне збирання командою деплою. Для CSV потрібні відповідна підтримка формату в боті та зміна `CONFIG_FILE`.

`secret.xlsx` містить тексти інтерфейсу, а `.secrets` — конфіденційні налаштування. Це різні файли.

## Медіапосилання в Excel

Медіафайли зберігаються поруч зі звітом на SMB-шарі, у папці `reports\media`. Наразі гіперпосилання у звіті містять внутрішній шлях контейнера:

```text
/mnt/share/reports/media/filename.jpg
```

Такий шлях не відкривається безпосередньо у Windows-Excel. Для доступу з Windows потрібен UNC-шлях:

```text
\\10.10.110.146\share\reports\media\filename.jpg
```

Запис UNC-посилань у клітинки потребує окремої зміни генератора Excel-звіту. Комп'ютер, на якому відкривають звіт, також повинен мати доступ до SMB-шари.
